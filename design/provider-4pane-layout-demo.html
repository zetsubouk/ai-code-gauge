设计决策：双模式供应商怎么识别？

推荐「按 API Key 自动识别 + 设置页手动覆盖」：MiMo 官方文档明确按量 Key 为 sk- 前缀、Token Plan Key 为 tp- 前缀（两者 Base URL 也不同），Key 本身携带计费模式，自动识别零负担；无前缀区分的厂商退化为手动选择。注册表契约相应扩展：modes 声明支持的额度形态，detectMode(cfg) 按 Key 判定，卡片模板按模式分发。

布局规则汇总（实现时的自适应口径）

1 家 = 单栏 360px；2 家 = 双栏 560px（现状）；3–4 家 = 2×2 网格 560px（3 家时最后一格留空或跨列）；>4 家 = 2×N 多行，弹窗内部滚动。
徽章循环条数 = 启用供应商数，逻辑不变；阈值提醒按各供应商当前模式的口径触发（套餐 = 窗口百分比 ≥95%，余额 = 余额 ≤ 设定金额）。
注册表扩展：modes: ["plan","balance"] + detectMode(cfg)（Key 前缀判定，可被设置覆盖）；历史快照按 供应商.模式.窗口 分键存储。
